# Public Library Content Catalog

Research-backed editorial reference for the public library (`publicStories`). This file is the
source of truth for what we make and why: category strategy, archetypes, tropes, tags, title
conventions, and the current batch slate. The machine-readable version of the slate lives in
[`specs.mjs`](./specs.mjs); the generator is [`generate.mjs`](./generate.mjs).

Research window: 2024–2026 coverage of ASMR, audio roleplay, and audio-erotica platforms
(Quinn, Dipsea, GoneWildAudio ecosystem, sleep podcasts, romantasy audiobooks). Sources at the
bottom.

## 1. Category tiers (what actually gets listened to)

### Tier 1 — proven, high-demand cores

| Category | Evidence |
|---|---|

| **Romantasy / spicy fantasy romance** | Dominated Spotify's 2025 Wrapped audiobooks (*Fourth Wing*, *ACOTAR*); Spotify predicts 2026 momentum. Quinn's flagship *Ember & Ice* is gay romantasy. |

### Tier 2 — strong and growing

| Category | Evidence |
|---|---|
| **Dark romance / MDom** (18+) | Quinn's co-#1 category ("Christian Grey-type vibes"); dark romance hit mass retail (Target/B&N) in 2025. |
| **Comfort / personal-attention ASMR** | Huge evergreen (Safe Space ASMR, "comfort for anxiety" formats; top creators built on soft-spoken personal attention). |
| **Monster romance** | "Genuine cultural movement" by 2025–26; cozy monster rom-coms (orc domesticity) are the distinct rising wave; appeal tied to a devoted partner who "can't leave you for someone better". |
| **Queer romance audio** | Dipsea headlines sapphic stories; Quinn's biggest 2025-26 bet was M/M for a primarily female Gen-Z audience (*Ember & Ice*, Slate). |

### Tier 3 — established niches / format plays

- **For-him (F4M) comfort + soft Fdom** — premium apps are near-exclusively M4F/M4M while ~15% of steamy-audio listeners are men and growing; GWA demonstrates the unmet demand. Underserved = opportunity.
- **Community amateur audio (GWA lineage)** — the trope R&D lab; taxonomy below.
- **Interactive / choose-your-path audio** — still nascent, no breakout hit; natural future fit for a Y/N app.

## 3. Trope & tag library

**Romance-structure tropes (BookTok/premium-app validated):**
enemies to lovers · forced proximity / only one bed · friends to lovers · strangers to lovers ·
slow burn · second chance · fake dating · grumpy/sunshine · age gap (adult, consensual) ·
arranged marriage · fated mates · touch-starved / "he falls first"

**Community-lineage content tags (popularity notes, names only):**
praise (top-tier perennial) · gentle/soft dom (the signature GWA-era tag) · comfort/wholesome ·
degradation (popular but OFF-CEILING for us) · breeding (high-demand, monster-adjacent; off-slate
this batch) · edging/orgasm control · size difference · soft Fdom for-him (underserved) ·
aftercare (now a format convention: short warm coda after intense audio — we bake this into
every nighttime story as a "warm landing" final beat)

### Platform ceiling (encoded in every spec)

- **In:** explicit consensual intimacy; power dynamics (MDom, soft Fdom); praise; possessive/
  "yandere-lite" intensity **with clear enthusiasm and consent on the page**; fated-mates
  devotion; sapphic and M/M content.
- **Out (this platform, all batches):** CNC/dubcon, degradation-heavy dynamics, humiliation,
  anything reading as coercion. Intense ≠ mean: even the dark stories end warm.

## 4. Title conventions (Quinn/Dipsea-coded)

- lowercase, 1–4 words, evocative **object / moment / place** — never a plot summary.
- name the charged detail: *the silk tie*, *heat lightning*, *one bed*, *porch light*.
- verbs and second person are fine when intimate: *stay on the line*, *sworn to him*.
- no narrator names in titles (the byline already shows the narrator).
- avoid: colons, title case, "a/the [adjective] [noun] story", anything that scans as a fanfic
  summary.

## 5. Format norms

| Format | Duration | Notes |
|---|---|---|
| Sleep/bedtime story | 15min | slow modes; ends settled, near-silent |
| Comfort / personal attention | 10–15min | warm, zero stakes |
| Spicy one-shot | 10min | the premium-app sweet spot for a scenario episode |
| Quick scenario | 5min | discovery/teaser content (none in this batch) |

- **Modes:** immersive is the house default (sparse, real-time, silences). Cinematic is reserved
  for fantasy scene-painting (fae court, lighthouse, orc hearth, knight's oath). Intermediate
  unused this batch.
- **Every nighttime story ends with a warm landing** (a few beats of after-glow/aftercare).
- Narrator pairs ladder SFW→NSFW: the same character has a daytime comfort story and a nighttime
  story ("sleepy boyfriend ladder" — the proven Quinn/Dipsea pattern).

## 6. Tag system

Flat `tags: string[]` on each public story, **2–3 tags, ordered vibe → hook → POV code**.
Card UI shows the vibe tag as a pill (bottom-left of the artwork) and the POV code as a second
pill (bottom-right); the player shows the full row; search matches tags. Vocabulary is enforced
by `validateSpecs()`:

- **vibe:** `sleep` `cozy` `sweet` `slow burn` `spicy` `dark` `praise` `soft dom` `dom` `possessive`
- **archetype:** `boyfriend` `girlfriend` `cowboy` `ceo` `bodyguard` `fae` `vampire` `werewolf` `orc` `knight`
- **trope:** `enemies to lovers` `one bed` `forced proximity` `fated mates` `second chance` `strangers to lovers`
- **pov (always last, exactly one):** `m4f` `f4m` `m4m` `f4f` — the community-standard
  [speaker]4[listener] code, derived from genderOther/genderSelf and validator-enforced.

Rules: one vibe tag always first; the POV code always last; never more than 3.

## 6b. Cover color scheme

One hue per shelf, all in the same dark tonal band (S ≈ 30–36%, L ≈ 27–28%), hues spaced ~40°
apart so shelves read as distinct sets that still belong to one library. Two close tones per
shelf alternate across cards (`COLLECTION_COLORS` in specs.mjs):

| shelf | tones | hue |
|---|---|---|
| bedtime | `#313E5E` / `#2A3652` | indigo |
| after dark | `#5D325D` / `#4F2A4F` | magenta-plum |
| dark romance | `#5E2C39` / `#4F2430` | oxblood |
| romantasy | `#3E315E` / `#362A52` | violet |

The card gradient derives from the single hex (`coverFromColor`: lighter top-left → base
bottom-right), so these are the only colors to maintain.
